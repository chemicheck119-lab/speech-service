# AIHub 광주 화재 신고음성 고정 평가

## 결론

`faster-whisper 1.2.1`의 `small`·CPU `int8` 기본 전사를 현재 기준선으로 선택했습니다. 사전 등록한 hotword 힌트는 핵심 용어 재현율을 높였지만 전체 문자 오류와 잘못된 용어 삽입을 함께 늘려 기본 설정에서 제외했습니다.

이 결론은 AIHub 신고접수 전화 음성에만 해당합니다. 실제 현장 무전 음성 성능을 검증한 결과가 아닙니다.

| 항목 | 상태 |

| 현장 무전 환경 성능 | 검증되지 않은 가설 |

## 데이터 범위

- 데이터 ID: `aihub_71768_gwangju_fire`
- 데이터 버전: `dataset-71768_downloaded-2026-09-05`
- 고정 평가 ID: `speech_aihub119_gwangju_fire_validation_77`
- Training: 659개 음성·라벨 쌍, 14.635시간
- Validation: 77개 음성·라벨 쌍, 1.752시간
- 형식: 8kHz, 모노, 16비트 WAV
- GCP 업로드: 광주 화재 ZIP 4개, 551,391,219바이트

원본 ZIP은 별도 오프라인 증강이나 재표본화를 하지 않았습니다. 평가 로더가 WAV를 제한된 임시 파일로 풀고, 라벨 발화를 시간순으로 결합하며, CER·WER 계산 시 유니코드·문장부호·공백을 결정적으로 정규화합니다.

스키마, 필수 필드, WAV 전체 payload, 화재 카테고리, 발화 시간 범위, 고정 레코드 수, 중복 PCM·전사문, Training/Validation 누수를 검사했습니다. 검사된 중복과 교차 split 누수는 0건입니다.

다만 라벨의 `audioPath` 값 736개 모두 다운로드한 ZIP 멤버를 직접 가리키지 않았습니다. WAV와 JSON 아카이브 멤버의 파일명 stem이 각 split에서 일대일이어서 이를 연결키로 사용했습니다. 이는 공급자 원본에서 추가 확인이 필요한 데이터 한계입니다.

## 비교 조건

두 조건은 다음 설정을 공유합니다.

- 모델: `small`
- 언어: 한국어 고정
- beam size: 5
- temperature: 0
- VAD: 사용
- 이전 구간 문맥: 사용하지 않음
- 레코드 실행 순서: 기본→hotword와 hotword→기본을 번갈아 배치

hotword 조건만 사전 등록한 11개 용어를 디코더 힌트로 전달했습니다. 평가 결과를 본 뒤 용어 목록을 수정하거나 전사문을 사후 치환하지 않았습니다.

false insertion은 레코드×용어 존재 여부 기준 개수이며 134개 음성 파일이 실패했다는 뜻이 아닙니다. 우선 용어 참조 양성도 같은 단위로 82개입니다.

레코드 단위 paired bootstrap 2,000회, seed 119로 계산한 `hotword CER - 기본 CER`은 `+0.12535`, 95% 구간은 `[+0.05916, +0.19248]`입니다. 구간 전체가 0보다 커 hotword 조건의 CER 악화가 일관됩니다.

RTF는 모델 추론시간만 포함합니다. Cloud Run의 컨테이너 시작, GCS 다운로드, 모델 초기화, 결과 업로드와 두 조건 전체 실행을 포함한 Job 경과시간은 45분 45초입니다.
